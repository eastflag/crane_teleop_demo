# 갠트리 크레인 원격조종 데모 (Isaac Lab)

조종실에 앉은 로봇이 스틱 2개와 패들을 조종하면 야드의 갠트리 크레인이 움직이고,
자석으로 철근을 흡착·운반하며, 패들을 밟으면 철근을 놓는 원격조종 데모 씬.

## 시나리오와 신호 흐름

```
[USB 게임패드]                    사용자(운전자)의 실물 입력
     │  왼스틱 x/y, 오른스틱 y, RT/A 버튼(패들)
     ▼
input_source.py                  데드존·응답커브·스무딩 필터
     ▼
cockpit.py                       3D 씬 안의 스틱 2개가 기울고,
     │                           조종실 로봇의 손(2본 IK)이 스틱 손잡이를 추적,
     │                           오른발은 패들을 밟는다
     ▼  (스틱 "측정값" = 필터된 명령)
crane.py                         갠트리: 포탈(Y)·트롤리(X)·권상(Z) 운동학
     │                           + 감쇠 진자로 후크 흔들림 모사
     ▼
magnet_logic.py                  자석 하부 필드 안의 철근 자동 부착(키네마틱 용접),
     │                           패들 → 해제(관성 유지 낙하)
     ▼
yard.py / 철근                    씬에서 유일한 동적 물리 객체 (중력·충돌)
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `demo.py` | 진입점. 앱 실행, 씬 조립, 메인 루프 |
| `config.py` | 모든 튜닝 상수(속도, 작업범위, 자석 필드, 카메라 등) |
| `input_source.py` | 게임패드 소스 + 하드웨어 없는 자동 파일럿(scripted) |
| `crane.py` | 갠트리 크레인 구조물 + 운동학 + 진자 후크 |
| `cockpit.py` | 조종실(캐빈·콘솔·스틱·패들·시트) + 조종 로봇 IK |
| `magnet_logic.py` | 자석 부착/운반/해제 |
| `yard.py` | 철근 강체 컬렉션 + 드롭존 표시 |
| `usd_utils.py` | USD 프리미티브 생성/갱신 헬퍼 |

## 설치 및 실행

요구: RTX GPU, Isaac Sim 4.5+, Isaac Lab 2.x

```bash
# 게임패드 지원(필요 시)
./isaaclab.sh -p -m pip install "isaaclab[gamepad]"   # SDL2 의존성

# 1) 하드웨어 없이 전체 사이클 자동 검증 (먼저 이것으로 씬 확인)
./isaaclab.sh -p crane_teleop_demo/demo.py --input scripted

# 2) 게임패드 조종
./isaaclab.sh -p crane_teleop_demo/demo.py --input gamepad --camera operator

# 무헤드 스모크 테스트(렌더 없이 N 스텝만)
./isaaclab.sh -p crane_teleop_demo/demo.py --input scripted --headless --max-steps 2400
```

## 조작 (게임패드)

| 입력 | 동작 |
|---|---|
| 왼쪽 스틱 좌우 | 크레인 X(동서) 이동 |
| 왼쪽 스틱 상하 | 크레인 Y(남북) 이동 |
| 오른쪽 스틱 상하 | 후크 상승/하강 (자석이 철근에 가까워지면 자동 부착) |
| RT 또는 A (누르는 동안) | 패들 → 자석 해제, 철근 낙하 |

스틱 위/아래 방향이 반대로 느껴지면 `config.py`의 `INPUT_INVERT_LY/RZ`를 True로.

## 데모 시나리오 (scripted 모드 자동 진행)

픽업존(더미 A) 상공 이동 → 하강 → 철근 4본 부착 → 상승 → 드롭존 이동 → 하강 →
패들(해제) → 복귀, 무한 반복. 콘솔에 2초마다 위치/흔들림/부착 수가 출력된다.

## v1 설계 결정 (왜 이렇게 구성했는가)

- **크레인·조종실·로봇은 물리가 아닌 운동학**: 조이스틱 데모의 본질은 "명령 → 동작"의
  응답성이다. 물리 액추에이터로 만들면 관성·제어 이득 튜닝이 추가로 필요해진다.
  대신 후크 흔들림은 감쇠 진자 방정식으로 사실적으로 표현했다.
- **물리는 철근에만**: 무게 중심이 데모의 재미(부착→운반→낙하)에 있으므로,
  동적 물리는 철근에 집중하고 나머지는 결정론적으로 움직인다.
- **로봇 손-스틱 결합은 IK 커플링**: 물리적 접촉으로 스틱을 밀면 조작감이 마찰 시뮬레이션
  상태에 좌우된다. 손이 스틱 손잡이를 항상 추적하도록 IK를 걸어 견고하게 했다.
- **자석 부착은 근접 판정 + 키네마틱 용접**: 실제 전자석도 일정 거리에서 달라붙으므로
  접촉 센서보다 근접 판정이 사실적이면서 노이즈에 강하다.

## 버전 호환 조정 포인트

이 코드는 Isaac Lab 2.x API 기준으로 작성되었다(작성 환경에 Isaac Lab이 설치되어
있지 않아 실행 검증은 되지 않았다). 오류 발생 시 아래 위치만 확인하면 된다.

| 증상 | 위치 | 조치 |
|---|---|---|
| Gamepad import 실패 | `input_source.py` `GamepadSource.__init__` | 모듈 경로/생성자 확인 |
| 게임패드 값이 0으로 고정 | `input_source.py` `AXIS_KEYS` | 첫 폴링에 출력되는 키 목록에 맞춰 후보 수정 |
| SimulationContext 생성 오류 | `demo.py` | `SimulationCfg`/생성자 시그니처(try/except 이미 있음) |
| InteractiveScene 생성 오류 | `demo.py` | `num_envs` 인자 위치(cfg vs 생성자) |
| 콜렉션 인덱스 의심 | `magnet_logic.py` 주석 | env_ids 평탄화 규칙(환경×객체수+객체) |
| GroundPlaneCfg 등 스포너 이름 | `demo.py` `YardSceneCfg` | `isaaclab.sim` 네임스페이스 확인 |

## v2 업그레이드 로드맵

1. **물리 스틱**: 스프링 복원식 2자유도 아티큘레이션 + 스틱 관절각을 측정값으로 사용
2. **실제 로봇**: 매네킹 대신 Franka 팔 2대 또는 G1(착석 고정) + `DifferentialIKController`
3. **물리 크레인**: 프리즘 조인트 3축 + 액추에이터, 하중 질량이 기구에 전달
4. **케이블 물리**: 구면 조인트 체인 또는 PhysX 로프
5. **자석 물리**: ContactSensor + 런타임 fixed joint(하중 관성 전달)
6. **캐릭터/환경 애셋**: Blender 제작 USD로 교체, 조종실 내부 UI 패널
